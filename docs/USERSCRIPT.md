# Gemini Search Bridge ユーザースクリプト版

Google検索語を、ログイン済みのGemini Webへ送信し、回答を検索結果内のカードへ表示します。
Tampermonkeyで動かす単一のスクリプトです。Gemini APIや外部サーバーは使いません。
バージョン0.3では、生成途中のテキスト表示、既存ウィンドウへの復旧操作と、任意のPiP補助表示に対応しています。

## ウィンドウを開いたまま使ってください

**使用中はGemini用ウィンドウの一部が見える状態にしてください。**
最小化、非activeタブへの移動、別ウィンドウによる完全な被覆で、
Chromeが描画やタイマーを抑え、回答の表示・取得が一時停止する場合があります。
送信済みのジョブは5分の期限内で維持し、ウィンドウを表示すると同じ回答の取得を再開します。
復旧操作で検索語を再送信することはありません。

この注意書きは初回の同意画面、Google検索カードの上部、Gemini用ウィンドウにも表示します。
Gemini画面の案内が操作に重なる場合は「×」で閉じられます。検索カードの注意書きは常に残ります。
初回はGeminiが前面に出る場合があります。既存ウィンドウへの復旧には、
Tampermonkeyが提供する`window.focus`権限を使います。
ウィンドウは自動で閉じません。

## PiP方式を試す

通常方式が既定です。検索カードの **「PiP方式（実験）」** をオンにすると、Gemini自身が
開くDocument Picture-in-Pictureの小窓を利用します。方式を変えると自動送信はオフになります。

1. 検索カードで「PiP方式（実験）」をオンにします。
2. 「Geminiウィンドウを開く」でGemini本体を表示します。
3. **Gemini側の「PiPを開く」を直接クリック**します。常に最前面の補助小窓が開きます。
4. Google検索へ戻り、「Geminiで生成」または「再生成」を押します。

小窓には生成状態と回答テキストを表示します。Gemini本体のDOMを移したり、iframeへ埋め込んだりはしません。
Gemini本体も開いたままにしてください。本体を閉じるとPiPも閉じます。

PiPを閉じると、その方式のジョブは取得待ちになります。Gemini側で「PiPを開く」を押し直すと、
同じ回答の取得を再開します。自動的に通常方式へ切り替えたり、検索語を再送信したりはしません。
生成開始前にPiPを閉じた場合は、開き直してから手動で再試行してください。

PiPを維持するため、この方式では新規チャットをGeminiのUI操作で開始します。
Geminiの再読み込みやページ移動でPiPが閉じた場合は、もう一度Gemini側のボタンを押してください。
PiP APIにはユーザー操作が必要なので、検索画面から自動でPiPを開くことはできません。

**この方式は実験オプションです。** ChromeにはPiP所有元の描画を維持する仕組みがありますが、
Gemini自身が非表示を検出して更新を止める場合は解決を保証できません。
利用できない環境や効果がない場合は、ジョブ終了後にチェックを外して通常方式を選んでください。
APIとウィンドウの制約は[Chrome公式説明](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)を参照してください。

## インストール

1. Chromeの **AI Agent** プロファイルでTampermonkey **5.5以降**を用意します。
2. 既存のGemini Search Bridge拡張を無効にして、二重送信を防ぎます。
3. Tampermonkeyの「新規スクリプトを追加」で初期コードを削除し、
   `gemini-search-bridge.user.js`の内容を貼り付けて保存します。
4. Google検索ページを再読み込みします。Chromeでスクリプト実行の許可を求められた場合は許可します。

ローカルファイルを直接開いてもインストール画面が出ない場合は、手順3の貼り付けで登録できます。

## 使い方

1. Googleで検索し、カードの案内を読んで「内容を確認して有効化」を押します。
2. 「Geminiで生成」を押します。Gemini用の別ウィンドウが開き、検索語が送信されます。
3. ウィンドウの一部を見える状態にして、Google検索へ戻ります。
   生成途中の文字が検索カードへ表示され、完成後に見出し・リストなどを整えた回答へ置き換わります。
4. 次の検索でも、開いたGeminiウィンドウをそのまま使います。毎回新しいチャットで生成します。

最初のクリックでポップアップがブロックされた場合は、Google検索サイトのポップアップを許可して再試行してください。
Geminiのログイン、CAPTCHA、モデル選択、規約確認、利用上限に関する操作は、ご自身で行ってください。
「Geminiウィンドウを開く」をもう一度押すと、既存ウィンドウへフォーカス要求を送ります。
Google検索ページを再読み込みした後や、応答確認が途切れた場合も既存ウィンドウを対象にします。
既存タブが閉じられていることを確認した場合だけ、新しいウィンドウを開きます。
その場合も未完了の検索語は再送信しません。

復旧を確認できない場合は、Tampermonkey 5.5以降であることと`window.focus`の許可を確認し、
タスクバーから表示してください。ブラウザやOSが最小化解除・前面化を拒否する場合があります。

### メモリセーバーと完全な被覆

メモリセーバーを使う場合は、Chromeの「設定 → パフォーマンス → 常にアクティブにするサイト」へ
`gemini.google.com`を追加すると、タブが無効化される問題の切り分けに役立ちます。
これは完全に覆われたウィンドウの描画抑制とは別の機能であり、除外だけで解消するとは限りません。
詳しくは[Chrome公式ヘルプ](https://support.google.com/chrome/answer/12929150?hl=ja)と
[ChromiumのWindows被覆検出の説明](https://chromium.googlesource.com/chromium/src/+/main/docs/windows_native_window_occlusion_tracking.md)を参照してください。

自動送信は初期状態でオフです。手動生成を確認してからオンにしてください。
自動モードでは、開いているGeminiウィンドウを使って検索語を送信します。
ウィンドウが閉じている場合は、もう一度「Geminiで生成」を押して開きます。
同時に処理する検索は1件です。別の検索が処理中なら、自動モードは待機し、手動モードは再試行を案内します。

## データと制約

- 設定はTampermonkeyのスクリプト用ストレージへ保存します。
- 生成途中の文字は最大約4回/秒で最新スナップショットを転送し、本文を連結せず差し替えます。
- 検索語と構造化回答は、同じストレージを使ってGoogleとGemini間で受け渡します。
  送信済みリクエストと受信済み回答は削除し、未受信の回答はGeminiウィンドウ稼働中に5分で削除します。
- 検索語や回答本文を診断ログへ記録したり、開発者サーバーへ送ったりしません。
  Gemini側のチャット履歴には残る場合があります。
- 通常のGeminiタブは操作しません。スクリプトが開いた専用ウィンドウだけが検索語を受け取ります。
- 非公開RPC、Cookieの取得、iframe、DNR、CAPTCHA回避は使いません。
- この版ではChrome拡張APIによるウィンドウ状態管理や破棄防止を使えません。
  Geminiの画面変更でセレクタが合わなくなった場合は修正が必要です。

## 開発

```powershell
npm run typecheck
npm test
npm run build
npm run build:dev
npm run build:userscript
```

生成先は`outputs/userscript/`です。新しい依存ライブラリは追加していません。
Gemini adapter、回答observer、extractor、検索カードは拡張版と共用しています。

## 検証状況

型チェック、118件のUnit Test、ユーザースクリプトと拡張の本番・開発ビルドを確認しました。
AI AgentプロファイルのChromeで、GM通信を模したローカルDOM試験を実施し、
5件連続の途中テキスト・完成回答表示、テキストの安全表示、Google再読み込みと応答確認の失効後の
フォーカス要求、同じジョブの取得再開、再送信なしを確認しました。
非表示のまま期限を超えたジョブは正常完了として扱わないことも確認しています。

実際のDocument PiP APIで、手動起動・文字更新・開閉・所有元の再読み込み時の終了を確認しました。
PiPとGM通信を模した試験では、非表示の所有元からの回答転送、PiP閉鎖後の取得待ちと開き直し、
同じ小窓・同じ元文書を使った2件連続の新規チャットを確認しました。

自動ブラウザの起動フラグは背景抑制を弱める場合があるため、API試験は描画継続の効果の証明には使っていません。

接続先ChromeにはTampermonkeyが未導入のため、実際のTampermonkeyとGeminiアカウントでの
生成試験とOSによる最小化解除・前面化は未確認です。
インストール後、まず手動で1件の生成と「Geminiウィンドウを開く」による復旧を確認してください。

実GeminiでのPiP方式の効果、Tampermonkeyの実行環境でのAPI利用、新規チャット操作が元文書を維持するかは未確認です。
まず手動で1件、その後2件目が同じPiPで処理できるかを確認してください。
