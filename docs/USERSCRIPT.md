# Gemini Search Bridge — PiP版 v0.5.0

Google検索にGeminiの回答を表示するTampermonkey用スクリプトです。
検索語をテンプレートへ差し込み、ログイン中のGemini Web画面へ自動で入力・送信します。生成途中の文章も検索カードへ反映します。英語の案内は[README](../README.md)、日本語のインストール手順は[README.jp](../README.jp.md)を参照してください。

## インストール

ChromeとTampermonkey 5.5以降を使用してください。Chromeの拡張機能設定でTampermonkeyのユーザースクリプト実行を許可します。
`outputs/userscript/gemini-search-bridge.user.js` をTampermonkeyへインストールします。
旧版と同時に2本有効にせず、同名スクリプトを更新してください。

v0.4.2では、Geminiの質問欄の読み上げ用ラベルを除き、実際の質問本文だけで会話を照合します。

v0.4.xからv0.5.0への更新後は、Google検索と既存のGemini本体を両方再読み込みし、PiP開始ボタンを押し直してください。更新前の途中検索を新しいテンプレートで自動再送しません。
v0.4の同意・消費済み検索・終端receiptは維持します。v0.3以前の同意・自動送信設定は引き継ぎません。

## 使い方

1. Google検索カードの「Geminiウィンドウを開く」を押します。
2. Gemini側に表示された説明を確認し、「PiPを開いて自動送信を開始」を直接押します。
3. Google検索へ戻ります。現在の検索語が送られ、次の検索も自動で送られます。

自動送信の設定スイッチはありません。PiP小窓の表示が送信の実行条件です。
**PiP小窓が表示されている間は、元のGeminiウィンドウを最小化できます。ただし閉じないでください。**
小窓を最小化・終了しないでください。ChromeやOSの状態によって描画が止まる場合は、元のGeminiも復元してください。
元のGeminiを閉じたり再読み込みしたりすると、所有するPiP小窓も閉じます。

PiPを閉じると新しい検索の自動送信は停止します。生成中の検索語を再送することはありません。
Gemini側でPiPを開き直すと、同じ回答の取得を再開します。接続待ちの期限は検索開始から5分です。
検索語を連続して変えた場合は、実行中の回答が終わるまで最新1件を待機させます。

v0.4.1では、回答完了後にGoogle検索を再読み込みしても、5分以内なら同じ検索・タブの受理記録から回答を復元します。検索語が変わらないURL更新でも回答を保持し、再送信はしません。
v0.4の旧記録には復元に必要な会話ジョブ情報がない場合があります。その場合は復元不可の案内を表示します。更新後の動作確認には別の検索語を使ってください。

## Geminiの操作が必要な場合

検索カードの同じ「Geminiウィンドウを開く」ボタンで、既存ウィンドウへフォーカスを要求します。
復元を確認できない場合はタスクバーから復元し、Tampermonkeyの`window.focus`許可を確認してください。
閉じたウィンドウは、ボタンを押したときに作り直します。中断した検索語は自動再送しません。

ログイン、CAPTCHA、利用上限、利用規約、モデル選択などで止まったときは「Gemini画面を確認」から直接操作します。
右下の「小窓の設定を開く」で起動案内へ戻れます。エラーになった検索を無断で再送しません。
失敗した検索や復元できない検索には「この検索を再送信」を表示します。Gemini側では既に回答が生成されている場合があるため、送信状況を確認してから押してください。同じ検索語を新しいジョブ・新規チャットとして1回送信します。
このボタンを押さない限り、PiP再開・フォーカス復元・ページ再読み込みでは再送しません。PiP準備中・別の回答の処理中は再送できません。
生成中に別のGeminiチャットへ移動すると、回答の取り違えを防ぐため取得を停止します。

## Google検索の表示

初期カードは起動ボタンだけです。生成が始まると状態と文章を表示します。途中回答・完成回答とも高さは最大210pxまたは画面高の27.5%までです。長い回答だけ「もっと見る」を表示し、全文・出典を展開できます。「折りたたむ」で戻せます。
本文直後の全幅ボタン「Geminiを開いて会話を続ける」は、現在の検索で生成された実際の会話ページを開きます。会話URLを確認できない間は表示しません。未展開の長文ではこの会話ボタンを隠して「もっと見る」だけを表示し、全文展開後は会話ボタンの次に「折りたたむ」を表示します。短文は会話ボタンだけです。
正常にPiPが開いている間、または正常な回答表示中の「Geminiウィンドウを開く」は、エリア右下の小さな補助ボタンになります。PiP準備完了であれば、回答がまだない待機・送信中も同じ配置です。
上部の「AI モード」は識別できた場合に「Gemini」へ変更し、左のGeminiアイコンで区別します。下線はなく、文字色は非アクティブ項目に合わせます。回答カードと同じ会話を開きます。
会話がまだ不明の場合だけ、Geminiのトップページへ移動します。検索を変えると古い会話との紐付けは解除します。

GoogleのAI回答は、既知のAIモジュールを識別できた場合だけ非表示にします。v0.4.4では、属性が内側へ移った非同期表示の構造も判定し、確認済みの専用外枠と所属する「もっと見る」を非表示にします。
ナビゲーションのGeminiリンクは、Google標準の配置クラスとラベル構造を保ち、他の項目と同じ行に揃えます。
通常の検索結果や検索全体の領域は隠しません。GoogleのDOMに公開された安定仕様はなく、表示変更により識別できなくなる場合があります。
通常結果と共有する枠や、未確認のAI外枠は畳まず、本文だけを隠す安全側の動作になります。
その場合はAI回答を残します。スクリプトを無効化して検索ページを再読み込みすれば元に戻ります。

## 表示言語とプロンプト設定

Tampermonkeyメニューの「Gemini Search Bridge 設定」、またはGemini側の「言語・プロンプト設定」から設定regionを開けます。表示言語はブラウザー追従・日本語・英語で、回答本文は翻訳しません。
既定送信文は日本語`ウェブ検索し参照を明示: %%prompt%%`、英語`Search the web and cite your sources: %%prompt%%`です。既定のチェックを外すと、`%%prompt%%`を含むカスタムテンプレートを保存できます。すべてのplaceholderをliteralに置き換え、テンプレート4096文字、送信文16384文字を超えると送信を止めます。
待機開始時に送信文を固定してタブ状態にも保存します。設定の変更だけで同じ検索を再送しません。複数行の行頭・行末空白はGemini表示と照合できない場合があります。

## 制限とデータ

PiPの開始にはGemini側の直接クリックが必要です。検索後やページ読み込み時の無操作起動は行いません。
Gemini自身のUIをDOM操作する非公式連携なので、Geminiの変更で動かなくなる可能性があります。
Native質問欄の段落境界の空白は表示用として除きます。行頭・行末の空白を意図的に含める複数行検索は照合できない場合があり、その場合は送信済みチャットをGeminiで確認してください。
Gemini API、非公開RPC、Cookieの直接取得、CAPTCHA回避、iframe、Offscreen、DNR、外部バックエンドは使用しません。

検索語・回答は、タブ間通信のためTampermonkeyのローカルストレージへ一時保存します。開発者サーバーへは送りません。
重複送信防止と回答復元のため、検索語の署名・ジョブ参照はタブ状態にも保持します。受理記録の期限後も、タブを閉じるまでこの参照が残る場合があります。
受理記録と回答は5分で期限切れになり、動作中のGemini workerが削除します。全ウィンドウを閉じている間はタイマーを実行できないため、次回起動時に削除します。
検索語や回答本文のtrace・外部ログは保存しません。Gemini側の履歴保存や利用枠はユーザーのアカウント設定に従います。

## 開発

```powershell
npm ci
npm run typecheck
npm test
npm run build
```

`src/userscript/` の入口・検索送信・worker・PiP・画面を分割し、Gemini adapter、observer、extractorを再利用しています。
Viteで単一の `.user.js` にバンドルします。`minify: false` のため配布コードも読める状態です。

ローカルブラウザ試験は `npm exec vite -- --host 127.0.0.1 --port 43721 --strictPort` で起動し、
`/tests/browser/smoke.html` を開きます。模擬DOMとGMストレージで動作し、Geminiへ検索を送信しません。
`/tests/browser/preview.html?view=worker` は実際のnative PiPと起動画面、`?view=answer` は回答カードの外観確認用です。
実装上の境界と表示仕様は [DESIGN.md](DESIGN.md) を参照してください。
